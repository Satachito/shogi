# 将棋道場 — Claudeと学ぶ将棋

将棋のルールを知らない人が、**指しながら覚えられる**ようにしたWebアプリです。
インストールもビルドも不要。`index.html` をブラウザで開くだけで動きます。

---

## つかいかた

いちばん簡単な方法：

ターミナルでこのフォルダに移動して

```bash
node bridge.js
```

を実行し、ブラウザで `http://localhost:8765/` を開いてください。

**対局するには bridge.js が必要です。** 相手の指し手は bridge.js 経由で受け取る作りなので、
これを起動していないと相手が指してくれません（画面の入力欄から手で入れることは可能です）。

`index.html` をダブルクリックして直接開くこともできますが、その場合は
盤を並べて眺めるだけになります（対局・講評・ヒント・形勢バーはすべて bridge.js が必要です）。

## できること

### 対局
- 8種類の駒、成り、持ち駒、二歩・打ち歩詰め・行きどころのない駒まで**将棋のルールを完全に実装**しています。反則手はそもそも指せません。
- 駒をクリックすると**動けるマスが光ります**。持ち駒をクリックすれば打てるマスだけが光ります。
- 手合割は **平手／香落ち／角落ち／飛車落ち／二枚落ち／四枚落ち／六枚落ち／八枚落ち**。初めてなら八枚落ちからどうぞ。
- **先手・後手を選べます**。後手を選ぶと相手から指し始め、盤はあなたの駒がいつも下側に来るように向きが変わります（筋・段の目盛りも一緒に反転します）。駒落ちのときは、駒を落とすのは常に相手のほうです。
- **待った**（何度でも）、**ヒント**、**詰みチェック**（1手詰・3手詰を探します）つき。
- **相手が指すたびに「次の一手」が出ます。** 指し手そのもの（`▲7六歩(77)`）と狙いのマス、
  そして**その先の読み筋**を示し、**「この手を指す」ボタン**でそのまま指せます。
  自分で考えたい人は ⚙ の設定で切れます。

#### ヒント通りに指せば勝てるようになっています

ヒントは**必ず、やねうら王がその局面で見つけた最善手**です。しかも

| | 読みの深さ | 考える時間 |
|---|---|---|
| ヒント | **無制限** | 相手の2.5倍（最低2秒） |
| 相手 | `SHOGI_USI_DEPTH` で制限 | `SHOGI_USI_BYOYOMI` |

と、**ヒント側が必ず相手より深く長く読みます**。実際に同じエンジンどうしで
（ヒント側=深さ無制限2.5秒 / 相手=深さ4・1秒）指し切らせて確かめました。

```
ヒント側 先手 → ヒント側の勝ち（詰み・45手）
ヒント側 後手 → ヒント側の勝ち（詰み・34手）
```

ただし**将棋に絶対の勝ちはありません**。ヒントを外した手が混ざれば、そのぶん形勢は動きます
（そのときは講評が「もっと良い手がありました」と教えます）。
相手を強くしたければ `SHOGI_USI_DEPTH` を上げてください — 上げるほどヒント通りでも勝てなくなります。
- **相手が指すと駒が滑って動き、指したマスが光ります。** どこが動いたか見逃しません。
- 相手の手は **`bridge.js` 経由で受け取ります**（やねうら王などのUSIエンジン／Claude／手入力）。
  そのため**対局には `node bridge.js` の起動が必要です**（後述）。

### 先生（右のパネル）

**このアプリに思考ルーチンも、用意した解説文もありません。** 出しているのは
**やねうら王が実際に読んだ内容そのもの**です。

指すたびに、あなたの手と最善手の**点差**が出ます。

```
ほぼ最善です
▲1八香車(19)
最善は ▲2六歩(27) で、180点の差でした。
その読み筋：▲2六歩 △8四歩 ▲7六歩 △8五歩 ▲2五歩 △3二金 ▲7七角行 △3四歩
やねうら王 深さ20
```

ヒントも同じで、**その手を選んだ理由を読み筋で示します**。「歩を伸ばして道を作る手です」
のような、駒の種類だけで決まる当たり障りのない説明はしません。

- **先生** … 講評・ヒント・読み筋
- **棋譜** … 指し手の一覧と形勢バー（先手・後手どちらを持っても「あなたから見た」形勢）
- **駒の動き** … 8種類の駒の利きを図で表示（成った駒も切り替え可）

`bridge.js` に繋がっていないときは、憶測でほめたり叱ったりせず「判定できません」と言います。

## チャットで盤面について相談する

いま指している局面を、Claude とのチャット（Claude Code など）に持ち込んで
「この局面どう指せばいい？」と相談できます。方法は2つ。

### 方法1：コピーして貼る（準備なし）

対局画面の **「チャットに貼る」** を押す → 「コピー」→ チャットに貼り付け。
盤面図・持ち駒・手番・SFEN・棋譜がまとめて入っているので、これだけで話が通じます。

逆に、チャットで教わった局面を試したいときは **「局面を読み込む」** に貼り付けます。
`SFEN: …` の行が含まれていれば、まわりの説明文ごと貼って構いません。

### 方法2：自動で共有する（コピペ不要）

ターミナルでこのフォルダに移動して

```bash
node bridge.js
```

を実行し、表示された **http://localhost:8765/** でアプリを開きます。
対局画面に「● チャット連携ON」と出れば成功で、**1手指すごとに `current-position.txt` が更新されます。**

あとはチャットで「いまの局面どう？」と聞くだけです（相手が `current-position.txt` を読みます）。
貼り付ける手間がないので、対局しながら相談するのに向いています。

### bridge.js が受け付けるもの

| 入り口 | 用途 |
|---|---|
| `GET /`（ほか静的ファイル） | アプリの配信 |
| `GET /bridge-ping` | 連携の確認。相手の思考設定（byoyomi・depth）も返します |
| `POST /position` | いまの局面を `current-position.txt` に書き出す |
| `GET /move?since=N&sfen=…` | 相手の指し手を取りに行く（局面が一致するものだけ返します） |
| `POST /move` | 相手の指し手を渡す |
| `POST /analyze` | 局面をエンジンに解析させる（講評・ヒント・形勢バーが使います） |

`POST /analyze` は `{"sfen": "…", "ms": 700, "multipv": 1}` を送ると
`{"bestmove": "7g7f", "depth": 20, "candidates": [{"move": "7g7f", "score": 106, "pv": […]}]}`
を返します（詰みのときは `score` ではなく `mate`）。

- 待ち受けは `127.0.0.1` だけ。外部からは接続できません。
- 書き込むのは `current-position.txt` の1ファイルだけです。
- 止めるときは Ctrl-C。ポートを変えたいときは `SHOGI_PORT=8766 node bridge.js`。
- 追加インストールは不要です（Node.js の標準機能だけで書いてあります）。

## 相手役を外部のAIにやってもらう

相手の手は必ず bridge.js から入るので、USIエンジンの代わりに
**Claude Code / Cursor / ChatGPT など、好きなAIに指してもらえます。**

`node bridge.js` を動かしておくと、相手の手番になるたび `current-position.txt` に
**盤面・手番・合法手の一覧**が書き出されます。あとはAIに指し手を返してもらうだけです。

### 指し手の渡し方（3通り、どれでもOK）

| 方法 | 向いているツール |
|---|---|
| `com-move.txt` に指し手を1行書く | Claude Code、Cursor など**ファイルを触れる**AI |
| `POST http://localhost:8765/move` に本文として送る | HTTPを叩けるツール、スクリプト |
| 画面の入力欄に貼って「この手で指す」 | ChatGPT など**ファイルを触れない**AI（答えをコピペ） |

### 指し手の書き方（どれでも読み取ります）

| 書き方 | 例 |
|---|---|
| USI（将棋ソフト共通） | `7g7f` / `7g7f+`（成る） / `P*5e`（歩を打つ） |
| 漢字 | `▲7六歩` / `7六歩` / `2四歩成` / `5二金打` |
| 数字 | `77-76` / `7776` / `77-76+` |

`▲△` の記号、全角、前後の空白は無視します。**迷ったら USI が確実**です。
合法手の USI 一覧が毎回 `current-position.txt` に入るので、そこから選べば間違いません。

反則手や読めない文字列が来たときは、**その場で理由を表示して指し直しを待ちます**
（勝手に別の手を指したりはしません）。

### AIに渡す指示の例

```
/Users/…/SHOGI/current-position.txt を読んで、あなたの手番なら
次の一手を決めて、その指し手だけを1行で /Users/…/SHOGI/com-move.txt に書いてください。
指し手は USI 形式（例: 7g7f）で、ファイルに書くのは1行だけにしてください。
```

## 本物の将棋ソフト（やねうら王）を相手にする

`bridge.js` は **USI**（将棋ソフト共通の規格）に対応したエンジンを相手役として使えます。
実行ファイルを置いて `node bridge.js` を起動するだけで、自動で見つけて使います。

```
思考エンジン                →  YaneuraOu MaterialLv1 9.60git 64APPLEM1
```

と表示されれば成功です。あとは普通に指せば、相手の手をやねうら王が返します。

相手の指し手は、USIエンジン・Claude・手入力のどれでも同じ入り口（bridge.js）から入ります。
アプリ側は誰が指したかを区別しないので、**bridge.js を再起動するだけで相手を差し替えられます。**

### エンジンの置き場所

次の順に探します。`SHOGI_USI_ENGINE` で明示するのが確実です。

1. 環境変数 `SHOGI_USI_ENGINE` のパス
2. `engine/yaneuraou`（このフォルダの中）
3. `../YaneuraOu/bin/yaneuraou-nnue`
4. `../YaneuraOu/bin/yaneuraou-material`

### 調整

| 環境変数 | 既定 | 意味 |
|---|---|---|
| `SHOGI_USI_BYOYOMI` | 1000 | 1手の思考時間（ミリ秒） |
| `SHOGI_USI_DEPTH` | 0 | 読みの深さ上限。0で無制限。小さくすると弱くなる |
| `SHOGI_USI_THREADS` | 1 | 思考に使うスレッド数 |
| `SHOGI_USI_FV_SCALE` | 20 | 評価値の倍率。評価関数ごとに推奨値がある（Háo は 20） |
| `SHOGI_USI_ANALYZE_MS` | 700 | 講評・ヒント・形勢の解析にかける時間（ミリ秒） |
| `SHOGI_USI_HASH` | 256 | 置換表のサイズ（MB） |

**`SHOGI_USI_DEPTH` は対局のときだけ効きます。** 講評・ヒント・形勢の解析は
毎回深さ無制限に切り替えて行うので、「相手は弱いが先生は強い」を同じエンジン1本でやれます。
ヒントの考える時間は `SHOGI_USI_BYOYOMI` の2.5倍（最低2秒）に自動で合わせます。

```bash
# 少し弱くして、じっくり考えさせる
SHOGI_USI_DEPTH=6 SHOGI_USI_BYOYOMI=2000 node bridge.js
```

### macOS (Apple Silicon) でのやねうら王のビルド

```bash
git clone --depth 1 https://github.com/yaneurao/YaneuraOu.git
cd YaneuraOu/source
make -j$(sysctl -n hw.ncpu) normal \
  TARGET_CPU=APPLEM1 \
  YANEURAOU_EDITION=YANEURAOU_ENGINE_MATERIAL \
  COMPILER="clang++ -isysroot $(xcrun --show-sdk-path)"
```

**`-isysroot` が要ります。** Makefile は `APPLEM1` 指定時に `-target arm64-apple-macos11`
を渡しますが `-isysroot` を付けないため、clang が macOS SDK を見つけられず
`'cstring' file not found` で全ファイルのコンパイルに失敗します。

- M1〜M4 すべて `TARGET_CPU=APPLEM1` を指定します
- **エディションを変えるときは先に `make clean`。** しないとオブジェクトが再利用され、
  指定と違うものができます
- `YANEURAOU_ENGINE_MATERIAL`（駒得のみ）は**評価関数ファイル不要でそのまま動きます**
- `YANEURAOU_ENGINE_NNUE` は別途 `nn.bin` が必要です（次項）

### 評価関数（NNUE）の入れ方

`YANEURAOU_ENGINE_NNUE` は halfkp_256x2-32-32 という構造の評価関数を使います。
**構造が一致しないファイルは読み込めません。** この構造で無料で入手できるいちばん強いものが
**Háo（ハオ）** です。

```bash
curl -L -o hao.7z https://github.com/nodchip/tanuki-/releases/download/tanuki-.halfkp_256x2-32-32.2023-05-08/tanuki-.halfkp_256x2-32-32.2023-05-08.7z
7zz x hao.7z                      # brew install sevenzip
cp eval/nn.bin <実行ファイルと同じ場所>/eval/nn.bin
```

- **`nn.bin` は実行ファイルと同じ階層の `eval/` に置きます**（エンジンは自分のいる場所から探します）
- Háo は **`FV_SCALE` を 20** にするのが推奨です（bridge.js が自動で設定します）
- ダウンロードは 23MB、展開後の `nn.bin` は 61MB、ライセンスは GPL-3.0

より強い評価関数（水匠10・11 など）は**スポンサー限定または有償**で、かつ別の構造なので
`YANEURAOU_EDITION` を変えて再ビルドする必要があります。強さの一覧は
[やねうら王のインストール手順](https://github.com/yaneurao/YaneuraOu/wiki/やねうら王のインストール手順) にあります。

## Claude連携（任意）

⚙ の設定から Anthropic の APIキーを入れると、**本物の Claude** が局面を日本語で解説してくれます
（対局画面の「Claudeに聞く」ボタン）。

- キーを入れなくても、**上に書いた機能はすべて使えます**。対局相手と「先生」は、このアプリに内蔵した将棋エンジンです（Claude ではありません）。
- APIキーはこの端末のブラウザ内（localStorage）にだけ保存され、Anthropic 以外には送信されません。
- 使ったぶんの API 料金がかかります。**共用のパソコンでは使わないでください。**
- モデルは Claude Opus 5 / Sonnet 5 / Haiku 4.5 から選べます。
- この機能を使うときは、`file://` ではなく `node bridge.js` 経由で開いてください（ブラウザの制限で通信がブロックされることがあります）。

## ファイル構成

```
index.html          画面
css/style.css       見た目
js/rule.js          将棋のルール（盤・手生成・詰み判定・SFEN）
js/pieces.js        「駒の動き」パネルの解説データ
js/AI.js            Claude API 連携（任意）
js/ui.js            画面の組み立てと操作
bridge.js           チャット連携用のローカルサーバー（任意・Node.js）
test/               ルールの自己テスト
```

`bridge.js` を動かすと `current-position.txt`（いまの局面）が作られます。
外部AIに相手役をさせるときは、AIが `com-move.txt`（相手の指し手）に書き込みます。

外部ライブラリは使っていません（アプリもサーバーも素の JavaScript だけ）。

## テスト

```bash
node test/test-rule.js
```

ルールの検証です。駒の動き・成り・二歩・打ち歩詰め・ピン・undoの整合性などに加えて、
**perft**（一定手数までの合法手の総数）を将棋で知られている値と照合しています。

| 深さ | 局面数 |
|---|---|
| 1 | 30 |
| 2 | 900 |
| 3 | 25,470 |
| 4 | 719,731 |

ここが合っていれば、手生成にほぼ間違いはありません。

## 既知の制限

- 棋譜の表記に「右・左・直」の区別を入れていないため、代わりに移動元を `▲5八金(69)` のように括弧で示しています。
- 千日手は同一局面4回で引き分けとしています。連続王手の千日手（反則負け）は判定していません。
- 入玉宣言勝ち（27点法）には対応していません。
- ページを開き直すと局面は復元されますが、それ以前の手には「待った」で戻れません。
- 「局面を読み込む」で読み込んだ局面は、そこからの新しい対局として扱われます（それ以前の棋譜は引き継ぎません）。
- 対局相手・講評・ヒント・形勢バーはすべて `bridge.js` 経由です。`bridge.js` を起動していないと、
  対局はもちろん、講評・ヒント・形勢バーも出ません（盤を並べて眺めることはできます）。
